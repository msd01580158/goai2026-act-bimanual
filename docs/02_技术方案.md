# 技术方案

## 1. 任务与观测建模

- **机器人**：arx_x5 双臂机器人。
- **动作空间**：14 维关节动作 —— `[左臂 6 关节, 左夹爪 1, 右臂 6 关节, 右夹爪 1]`，由 `get_robot_action_dim_info("arx_x5")` 解析，动作类型 `joint`。
- **观测空间**：三目视觉 + 关节状态。
  - 相机：`cam_head`（头部）、`cam_left_wrist`、`cam_right_wrist`（双臂腕部），图像统一为 **640×480** RGB。
  - 状态：左右臂关节角 + 夹爪开合（与动作空间同维，14 维）。
- **控制频率**：状态/动作以固定频率同步，策略采用时序聚合在动作块之间平滑插值，保证控制连续性。

## 2. 数据

- **来源**：RoboDojo 基准提供的 12 个 GOAI 任务演示数据。
- **规模**：每任务 **100 个演示 episode**，以 hdf5 存储（`state/`、`action/`、`vision/` 三组），原始图像为 JPEG 编码，含相机内外参。
- **本地数据**：Assets 33G + 数据 155G（12 任务全量）。

## 3. 数据预处理（RoboDojo 格式 → ACT 标准格式）

原始 hdf5 为 RoboDojo 新格式（`state/`、`action/`、`vision/`），与 ACT 训练器期望的 `observations/qpos` + `observations/images` + `action` 结构不同。预处理管线 `detr/process_data.py`：

1. 用 `pack_robot_state` 将左右臂关节/夹爪状态打包为 14 维 `qpos` 与 `action`；
2. 将每帧 JPEG 图像解码并 `cv2.resize` 到 640×480；
3. 写入标准 hdf5：`observations/qpos`、`observations/images/{cam_head,cam_left_wrist,cam_right_wrist}`、`action`；
4. 图像以**逐帧 gzip 分块**存储，兼顾磁盘占用与随机读取速度；
5. 自动生成 `TASK_CONFIGS.json`，登记每任务的数据目录、episode 数与相机列表。

## 4. 策略模型：ACT

采用 **ACT（Action Chunking with Transformers）**，由两个关键机制构成：

- **动作分块（Action Chunking）**：一次推理输出一段长度为 `chunk_size=50` 的动作序列，显著降低高频控制下的累积误差与推理频率要求；
- **Transformer 编码器-解码器 + VAE（CVAE）**：以当前/历史观测为条件，对动作分布建模，训练时引入 KL 正则。

### 关键超参数
| 参数 | 值 |
|---|---|
| Backbone | ResNet18（ImageNet 预训练） |
| 编码器/解码器层数 | 4 / 7 |
| Head 数 | 8 |
| Hidden dim | 512 |
| Feedforward dim | 3200 |
| Chunk size | 50 |
| Temporal aggregation | 开启 |
| KL weight | 10 |
| 批大小 | 16（22G GPU）/ 8（11.5G GPU） |
| 优化器 | Adam，lr 1e-5 |
| 训练轮数 | 短训 1000–2000 + 验证集筛选最优 |

## 5. 训练

- **损失**：行为克隆 —— 动作 L1 损失 + 掩码（padding）损失 + KL 正则。
- **数据划分**：每任务 100 episode 划分训练/验证集，验证集 loss 用于筛选最优 epoch 检查点。
- **训练产出**：每个训练运行保存 `policy_last.ckpt`（末轮）与 `policy_best.ckpt`（验证 loss 最优），连同 `dataset_stats.pkl`（归一化统计）一起构成可部署检查点。
- **训练硬件**：本机双卡（RTX 2080 Ti 22G + RTX 4000 Ada 11.5G）并行训练 12 任务。

## 6. 部署架构

```
主办方评测系统
      │  ws://36.212.51.4:10002   (msgpack 帧协议)
      ▼
[服务器 36.212.51.4 · 2×A100-40GB]
      │  tcp_forward.py 纯 TCP 转发
      ▼
[ACT Policy Server  127.0.0.1:6000]
   ├─ policy/ACT  (XPolicyLab 集成)
   ├─ prepare_case 多任务钩子
   └─ checkpoints/act-RoboDojo-<task>/
        └─ <run>/policy_last.ckpt + dataset_stats.pkl
```

- **评测服务**：`robodojo.sh server` 启动 ACT 策略服务，绑定 `0.0.0.0:6000`；`tcp_forward.py` 将公网 `10002` 端口转发到内网 `6000`，安全组放行 `10000–10033`。
- **协议**：`client_server/ws`，WebSocket + msgpack 帧，`MessageType` 支持 `PREPARE_CASE`、观测、动作等消息。

## 7. 多任务热切换（prepare_case）

在 `policy/ACT/model.py` 中实现 `prepare_case` 钩子：

1. 评测端发送 `PREPARE_CASE(action_case_id="<task>_case")`；
2. 服务端解析任务名，在 `checkpoints/act-RoboDojo-<task>/` 下定位含 `policy_last.ckpt` 与 `dataset_stats.pkl` 的目录；
3. 重新实例化策略并加载检查点，完成热切换（同任务重复请求则仅重置时序状态）；
4. 切换后可立即接受观测并输出动作。

由此，12 个任务共享一个公网端点，无需多次申请、无需重启。

## 9. 部署说明（如何复现）

### 9.1 服务器端（评测服务，运行中）

前置：conda 环境 `act`（python 3.10 / torch 2.4.1+cu121，含 `XPolicyLab` editable 安装）。

1. 启动 ACT 策略服务（绑定内网 6000）：
   ```bash
   cd ~/RoboDojo
   bash scripts/robodojo.sh server \
     --policy-dir XPolicyLab/policy/ACT --task stack_bowls \
     --ckpt /home/mashideng/RoboDojo/XPolicyLab/policy/ACT/checkpoints/act-RoboDojo-stack_bowls/arx_x5-100-joint \
     --policy-env act --action-type joint --env-cfg arx_x5 \
     --policy-port 6000 --bind-host 0.0.0.0
   ```
2. 启动公网 TCP 转发（10002 → 6000）：
   ```bash
   nohup python3 ~/tcp_forward.py > /tmp/tcp_forward.log 2>&1 &
   ```
3. 验证：`ss -tlnp | grep -E "6000|10002"`。

### 9.2 本机端（训练，可复现）

1. 数据转换（RoboDojo 原始 hdf5 → ACT 标准格式，自动生成 `TASK_CONFIGS.json`）：
   ```bash
   cd ~/RoboDojo/XPolicyLab/policy/ACT
   bash process_data.sh RoboDojo <task> arx_x5 joint
   ```
2. 训练（短训 + 验证集筛选最优检查点）：
   ```bash
   export ACT_ACTION_DIM=14 CUDA_VISIBLE_DEVICES=1
   python imitate_episodes.py \
     --bench_name RoboDojo --task_name <task> \
     --ckpt_setting RoboDojo-<task>-arx_x5-joint \
     --ckpt_dir checkpoints/RoboDojo-<task>-arx_x5-joint-run1 \
     --policy_class ACT --kl_weight 10 --chunk_size 50 --hidden_dim 512 \
     --dim_feedforward 3200 --batch_size 16 --num_epochs 2000 --lr 1e-5 \
     --save_freq 500 --seed 0
   ```
3. 部署检查点：将 `policy_best.ckpt`（或 `policy_last.ckpt`）与 `dataset_stats.pkl` 上传至服务器 `checkpoints/act-RoboDojo-<task>/<run>/`，并命名为 `policy_last.ckpt`。
