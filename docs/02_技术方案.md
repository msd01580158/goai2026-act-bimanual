# 技术方案

## 1. 任务与观测建模

- **机器人**：arx_x5 双臂机器人。
- **动作空间**：14 维关节动作 —— `[左臂 6 关节, 左夹爪 1, 右臂 6 关节, 右夹爪 1]`，由 `get_robot_action_dim_info("arx_x5")` 解析，动作类型 `joint`。
- **观测空间**：三目视觉 + 关节状态。
  - 相机：`cam_head`（头部）、`cam_left_wrist`、`cam_right_wrist`（双臂腕部），图像统一为 **640×480** RGB。
  - 状态：左右臂关节角 + 夹爪开合（与动作空间同维，14 维）。
- **控制频率**：状态/动作以固定频率同步，策略采用时序聚合在动作块之间平滑插值，保证控制连续性。

### 1.1 arx_x5 双臂平台技术规格

**机器人本体（dual_x5）**：仿真模型 `Assets/Robots/x5/ARX.usd`，对应真实 ARX X5 双臂机器人。

- **自由度结构**：每臂 6 关节 + 1 夹爪。关节链：`waist → shoulder → elbow → forearm_roll → wrist_angle → wrist_rotate`；夹爪为 2 个耦合关节，动作/观测统一暴露为 1 维（同步开合）。
- **动作空间**：14 维 —— `[左臂6, 左夹爪1, 右臂6, 右夹爪1]`，`action_type=joint`（关节角控制），由 `get_robot_action_dim_info("arx_x5")`（arm_dim [6,6] + ee_dim [1,1]）严格解析。
- **执行器（阻抗控制）**：

  | 部位 | 刚度 | 阻尼 | 力矩上限 | 速度上限 |
  |---|---|---|---|---|
  | 手臂 (joint1-6) | 4400 | 40 | 100 | 5.0 |
  | 夹爪 (joint7-8) | 2300 | 100 | 100 | — |

- **物理设置**：重力关闭、根关节固定、自碰撞开启、位置求解 8 次迭代；初始位姿 `pos(0.25,-0.25,0)`、绕 Z 旋转 90°。
- **观测**：14 维关节状态 + 世界系末端位姿；三目 RGB 视觉 —— 头部 `cam_head`（真实型号 **Gemini_345Lg** 奥比中光 RGB-D，pinhole 模型，安装 `pos(0,-0.41,1.308)`、俯仰 30°）+ 双臂腕部 `cam_left_wrist`/`cam_right_wrist`；图像统一 **640×480**；采样频率 **25Hz**。

## 2. 数据

- **来源**：RoboDojo 基准提供的 12 个 GOAI 任务演示数据。
- **规模**：每任务 **100 个演示 episode**，以 hdf5 存储（`state/`、`action/`、`vision/` 三组），原始图像为 JPEG 编码，含相机内外参。
- **本地数据**：Assets 33G + 数据 155G（12 任务全量）。

## 3. 数据预处理（RoboDojo 格式 → ACT 标准格式）

### 3.1 原始数据格式（RoboDojo 新格式 hdf5）

每任务 100 个 episode，每文件 `episode_XXXXXXX.hdf5`（以 stack_bowls 实测为例，241 帧/episode）：

```
episode_0000000.hdf5
├── state/                        # 观测状态
│   ├── left_arm_joint_states   (241, 6)   左臂6关节角
│   ├── left_ee_joint_states    (241, 1)   左夹爪开合
│   ├── left_ee_poses           (241, 7)   左末端位姿(位置3+四元数4)
│   ├── left_delta_ee_poses     (241, 7)   左末端增量
│   ├── right_arm_joint_states  (241, 6)   右臂6关节角
│   ├── right_ee_joint_states   (241, 1)   右夹爪开合
│   └── right_ee_poses          (241, 7)   右末端位姿
├── action/                       # 动作（双臂驱动，与 state 结构对应）
│   ├── left_arm_joint_states / right_arm_joint_states
│   └── left_ee_joint_states  / right_ee_joint_states
├── vision/                       # 三目视觉
│   ├── cam_head/               colors: (241,) |S89167  ← JPEG 编码字节
│   ├── cam_left_wrist/          （含内外参矩阵 + shape）
│   └── cam_right_wrist/
├── instruction                   # 语言指令: b'Stack the three bowls together.'
└── data_format_version / additional_info/
```

**特点**：① 双臂**分开存储**（left_/right_ 独立键）；② 图像为 **JPEG 编码字节**（非解压像素）；③ 每集带**语言指令**（为 VLA 预留）。

### 3.2 ACT 期望格式（旧格式）

ACT 训练器读取**扁平的通用格式**：
```
observations/
├── qpos      (241, 14)            单一状态向量
└── images/
    ├── cam_head / cam_left_wrist / cam_right_wrist   (241,480,640,3) uint8 像素
action    (241, 14)               单一动作向量
```

### 3.3 转换原因

| 差异点 | RoboDojo 原始 | ACT 需要 | 转换动作 |
|---|---|---|---|
| 双臂存储 | left/right 分开的键 | 单一向量 | `pack_robot_state` 打包 14 维 `[左6,左夹爪1,右6,右夹爪1]` |
| 图像编码 | JPEG 字节 (\|S89167) | uint8 像素 | 每帧 `decode_image_bit` 解码 |
| 图像尺寸 | 相机原始分辨率 | 640×480 统一 | `cv2.resize` |
| 目录结构 | state/action/vision 分组 | observations/qpos+images | 重组写盘 |
| 归一化 | 无 | 训练需均值/标准差 | 训练时算 `dataset_stats.pkl` |

**核心原因**：ACT 是通用行为克隆框架，期望固定输入格式；RoboDojo 是双臂多模态新格式（为 VLA 等多模型设计）。转换是**一次性预处理**，标准化后 ACT 训练代码零改动、可复用。

### 3.4 转换代码（`detr/process_data.py` 核心）

```python
from XPolicyLab.utils.process_data import (
    pack_robot_state, get_robot_action_dim_info, decode_image_bit,
)

robot_action_dim_info = get_robot_action_dim_info(env_cfg_type)  # arx_x5 → 14维
state_all  = pack_robot_state(data, 'joint', robot_action_dim_info,
                              source_type="dataset", state_type="state")
action_all = pack_robot_state(data, 'joint', robot_action_dim_info,
                              source_type="dataset", state_type="action")

# 每帧：解码 JPEG → resize 640×480 → 收集
cam_head = decode_image_bit(data['vision']['cam_head']['colors'][j])
cam_head = cv2.resize(cam_head, (640, 480))

# 写入 ACT 标准格式（本方案改进：图像逐帧 gzip 分块）
with h5py.File(hdf5path, "w") as f:
    f.create_dataset("action", data=np.array(actions, dtype=np.float32))
    obs = f.create_group("observations")
    obs.create_dataset("qpos", data=np.array(qpos, dtype=np.float32))
    image = obs.create_group("images")
    image.create_dataset("cam_head", data=np.stack(cam_head_list), dtype=np.uint8,
                         compression="gzip", compression_opts=4, chunks=(1, 480, 640, 3))
    # ... cam_left_wrist / cam_right_wrist 同理
```

**关键点**：
1. `pack_robot_state` 把双臂键打包为 14 维向量（与部署端 `get_robot_action_dim_info` 严格一致）；
2. `decode_image_bit` 解 JPEG → `resize` 640×480；
3. **逐帧 gzip 分块**：单任务 116G→~41G，且按帧独立 chunk 保证训练随机读取高效；
4. 转换后自动生成 `TASK_CONFIGS.json`（数据目录 + episode 数 + 相机列表）。

### 3.5 数据生命周期

转换数据按任务管理：训练完成并**成功上传服务器后立即删除**（防磁盘堆积）；上传失败保留并靠 watcher 兜底补传。详见 `docs/06_工程实践与部署经验.md`。

## 4. 策略模型：ACT

采用 **ACT（Action Chunking with Transformers）**，由两个关键机制构成：

- **动作分块（Action Chunking）**：一次推理输出一段长度为 `chunk_size=50` 的动作序列，显著降低高频控制下的累积误差与推理频率要求；
- **Transformer 编码器-解码器 + VAE（CVAE）**：以当前/历史观测为条件，对动作分布建模，训练时引入 KL 正则。

### 关键超参数
| 参数 | 值 |
|---|---|
| Backbone | ResNet18（ImageNet 预训练） |
| 编码器/解码器层数 | 4 / 7 |
| Head 数 | 8 |
| Hidden dim | 512 |
| Feedforward dim | 3200 |
| Chunk size | 50 |
| Temporal aggregation | 开启 |
| KL weight | 10 |
| 批大小 | 16（22G GPU）/ 8（11.5G GPU） |
| 优化器 | Adam，lr 1e-5 |
| 训练轮数 | 短训 1000–2000 + 验证集筛选最优 |

## 5. 训练

- **损失**：行为克隆 —— 动作 L1 损失 + 掩码（padding）损失 + KL 正则。
- **数据划分**：每任务 100 episode 划分训练/验证集，验证集 loss 用于筛选最优 epoch 检查点。
- **训练产出**：每个训练运行保存 `policy_last.ckpt`（末轮）与 `policy_best.ckpt`（验证 loss 最优），连同 `dataset_stats.pkl`（归一化统计）一起构成可部署检查点。
- **训练硬件**：本机双卡（RTX 2080 Ti 22G + RTX 4000 Ada 11.5G）并行训练 12 任务。

### 5.1 训练工程优化（本方案的提升细节）

针对 RoboDojo 新格式数据与受限算力环境，本方案在训练链路上做了以下工程优化：

1. **数据压缩存储（磁盘降约 2/3）**：原始图像经 JPEG 解码并 resize 640×480 后，以**逐帧 gzip 分块**（`compression="gzip"` + 每帧独立 chunk）写入 hdf5。相比无压缩存储，单任务数据从 ~116G 降至 ~41G，且因按帧独立分块，训练时的**随机帧读取仍保持高效**（仅解压所需帧）。这让 12 任务的全量转换在有限磁盘下可行。
2. **验证集筛选最优检查点（`policy_best.ckpt`）**：训练每轮在固定验证集上计算 loss，训练结束保存**验证 loss 最低**的 epoch 状态，而非盲目使用末轮权重。在短训练预算下兼顾收敛质量与泛化，避免过拟合到训练噪声。部署时上传 `policy_best.ckpt`（作为 `policy_last.ckpt`）。
3. **双卡并行批量训练流水线 + 预转换优化**：22G 卡跑 batch=16、11.5G 卡跑 batch=8，两卡并行训练不同任务；自动化驱动脚本按「转换 → 训练 → 上传 → 清理」循环调度 12 任务，训练成果自动上传服务器。**关键优化——预转换线程**：趁当前任务训练时（GPU 忙碌、CPU 有空闲），后台**提前把下一个任务的数据转换好**，使任务交接时 GPU **零空转**（实测最后 3 个任务交接全部即时开训）。转换与训练重叠进行，压缩总墙钟时间。
4. **跨 torch 版本部署兼容验证**：本机 torch 2.7.1 训练产出的 state_dict，在服务器 torch 2.4.1 环境加载并通过前向推理验证——确认检查点格式跨版本稳定，训练机与部署机解耦。
5. **数据标准化管线**：`pack_robot_state` 将双臂关节/夹爪统一打包为 14 维动作向量，与 `get_robot_action_dim_info("arx_x5")` 严格对齐，确保训练-部署动作语义一致。

## 6. 部署架构

```
主办方评测系统
      │  ws://36.212.51.4:10002   (msgpack 帧协议)
      ▼
[服务器 36.212.51.4 · 2×A100-40GB]
      │  tcp_forward.py 纯 TCP 转发

```

- **评测服务**：`robodojo.sh server` 启动 ACT 策略服务，绑定 `0.0.0.0:6000`；`tcp_forward.py` 将公网 `10002` 端口转发到内网 `6000`，安全组放行 `10000–10033`。
- **协议**：`client_server/ws`，WebSocket + msgpack 帧，`MessageType` 支持 `PREPARE_CASE`、观测、动作等消息。
- **Batch 推理**：支持 `update_obs_batch` / `get_action_batch`——一次提交 N 个仿真环境的观测，策略单次前向返回 N 个动作（每环境独立时序聚合，有界缓冲避免内存爆炸）。适配评测端多环境并行评测。

## 7. 多任务热切换（prepare_case）

在 `policy/ACT/model.py` 中实现 `prepare_case` 钩子：

1. 评测端发送 `PREPARE_CASE(action_case_id="<task>_case")`；
2. 服务端解析任务名，在 `checkpoints/act-RoboDojo-<task>/` 下定位含 `policy_last.ckpt` 与 `dataset_stats.pkl` 的目录；
3. 重新实例化策略并加载检查点，完成热切换（同任务重复请求则仅重置时序状态）；
4. 切换后可立即接受观测并输出动作。

由此，12 个任务共享一个公网端点，无需多次申请、无需重启。

## 8.1 RDT-1B 大规模 VLA：部署与演进路线

为从**行为克隆**向**具身 VLA（Vision-Language-Action）**升级，本方案已完成 RDT-1B 的部署验证，作为下一步演进的技术储备。

### RDT-1B 简介

**RDT-1B（Robotic Diffusion Transformer，10 亿参数）** 是面向双臂灵巧操作的**扩散基础模型**（Diffusion Foundation Model）。核心思路：先在海量双臂数据上预训练通用动作生成器，再按任务微调——类似大模型的「预训练 + 微调」范式。

### 架构：三模态输入 → 扩散生成

```
语言指令 ──► T5-XXL 文本编码器 ──┐
视觉观测 ──► SigLIP 视觉编码器 ──┼─► RDT 扩散 Transformer ──► 动作序列
关节状态 ─► 状态编码器 ─────────┘   （DiT 结构，1B 参数）
```

- **语言**：T5-XXL（42G 权重），理解任务指令，支持开放词汇指令
- **视觉**：SigLIP 图文对齐编码器，处理多视角图像
- **动作生成**：扩散模型（DiT）逐步去噪生成动作序列，对多峰动作分布建模更强

### 与双臂赛道契合

1. **D-STEP 双臂统一动作空间**：左右臂动作解耦编码，天然支持双臂协同（arx_x5）；
2. **异构动作统一**：可同时输出连续（关节角）与离散（夹爪）动作；
3. **语言引导泛化**：指令条件化带来更强的跨任务泛化，契合「泛化维度」评测方向。

### RDT-1B 替换 ACT 的验收门槛（可量化）

RDT-1B 只有在以下四个节点**全部达标**后才替换 ACT：

1. **数据节点**：12 任务数据转 RDT 格式（含 `instruction` 语言指令），与 ACT 共享预处理管线；
2. **训练节点**：RDT-1B 微调收敛（**LoRA + T5 显存卸载**，受限显存 22G 下可行），验证集 loss 达标；
3. **评测节点（硬门槛）**：微调版在评测端点/本地仿真上跑 12 任务（含**泛化维度**），**成功率 ≥ ACT 基线**；
4. **部署节点**：RDT 检查点部署服务器，多任务切换（`prepare_case`）扩展到 RDT，评测端可用 `PREPARE_CASE` 无缝切换。

> 只有 ③ 达标才替换，否则维持 ACT——保证策略质量只升不降。

1. **参数高效微调**：LoRA + T5 显存卸载，使 1B 扩散模型在受限显存（22G）下可微调；
2. **任务数据对齐**：12 任务数据按 RDT 格式组织，复用 ACT 预处理管线；
3. **评测对比**：以 ACT 结果为基线，在「泛化维度」上验证 RDT-1B 提升（对应验收门槛 ③）；
4. 相关部署验证脚本随开源计划开放，助力双臂 VLA 社区共建。

3. 部署检查点：将 `policy_best.ckpt`（或 `policy_last.ckpt`）与 `dataset_stats.pkl` 上传至服务器 `checkpoints/act-RoboDojo-<task>/<run>/`，并命名为 `policy_last.ckpt`。

## 11. 数据来源说明

- **数据内容**：RoboDojo 仿真基准的 12 个双臂操作任务演示数据，每任务 100 个 episode，hdf5 格式（含 `state/`、`action/`、`vision/`，图像为 JPEG 编码）。
- **数据规模**：Assets 33G + 演示数据 155G。
- **获取方式**：RoboDojo 基准官方数据发布渠道（Assets 通过 `scripts/init_assets.sh` 拉取；演示数据为 GOAI 评测指定子集）。
- **数据用途**：仅用于策略行为克隆训练与评测，与赛题一评测任务一一对应。
