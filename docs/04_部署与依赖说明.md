# 部署与依赖说明

## 部署架构

```
评测系统 → ws://36.212.51.4:10002 → [TCP 转发] → 127.0.0.1:6000 (ACT Policy Server)
```

云端评测服务器（2×A100-40GB）同时运行 ACT 策略服务与公网转发：

- 策略服务绑定 `0.0.0.0:6000`；
- `tcp_forward.py` 将公网 `10002` 转发至内网 `6000`，安全组放行 `10000–10033`。

## 服务器端部署步骤

前置：conda 环境 `act`（Python 3.10 / PyTorch 2.4.1+cu121，`XPolicyLab` editable 安装）。

```bash
# 1) 启动 ACT 策略服务
cd ~/RoboDojo
bash scripts/robodojo.sh server \
  --policy-dir XPolicyLab/policy/ACT --task stack_bowls \
  --ckpt ~/RoboDojo/XPolicyLab/policy/ACT/checkpoints/act-RoboDojo-stack_bowls/arx_x5-100-joint \
  --policy-env act --action-type joint --env-cfg arx_x5 \
  --policy-port 6000 --bind-host 0.0.0.0

# 2) 启动公网 TCP 转发
nohup python3 ~/tcp_forward.py > /tmp/tcp_forward.log 2>&1 &

# 3) 验证
ss -tlnp | grep -E "6000|10002"
```

## 多任务热切换

将 `act/model_multi_task.py` 放入 `XPolicyLab/policy/ACT/model.py`，并为每个任务准备检查点：

```
checkpoints/act-RoboDojo-<task>/
    └── <run>/
        ├── policy_last.ckpt     # 部署加载
        └── dataset_stats.pkl    # 归一化统计
```

评测端发送 `PREPARE_CASE(action_case_id="<task>_case")`，服务端解析任务名并热加载对应检查点。

## 本机训练步骤

```bash
cd <RoboDojo>/XPolicyLab/policy/ACT

# 1) 数据转换（RoboDojo 原始 hdf5 → ACT 标准格式，自动生成 TASK_CONFIGS.json）
bash process_data.sh RoboDojo <task> arx_x5 joint

# 2) 训练
export ACT_ACTION_DIM=14 CUDA_VISIBLE_DEVICES=1
python imitate_episodes.py \
  --bench_name RoboDojo --task_name <task> \
  --ckpt_setting RoboDojo-<task>-arx_x5-joint \
  --ckpt_dir checkpoints/RoboDojo-<task>-arx_x5-joint-run1 \
  --policy_class ACT --kl_weight 10 --chunk_size 50 --hidden_dim 512 \
  --dim_feedforward 3200 --batch_size 16 --num_epochs 2000 --lr 1e-5 \
  --save_freq 500 --seed 0

# 3) 部署检查点：将 policy_best.ckpt（或 policy_last.ckpt）与 dataset_stats.pkl
#    上传服务器 checkpoints/act-RoboDojo-<task>/<run>/，命名为 policy_last.ckpt。
```

## 数据来源

- **内容**：RoboDojo 基准的 12 个双臂操作任务演示数据，每任务 100 episode，hdf5（`state/`、`action/`、`vision/`）。
- **规模**：Assets 33G + 演示数据 155G。
- **获取**：RoboDojo 官方数据发布渠道（Assets 经 `scripts/init_assets.sh`；演示数据为 GOAI 评测指定子集）。
- **用途**：仅用于策略行为克隆训练与评测。
