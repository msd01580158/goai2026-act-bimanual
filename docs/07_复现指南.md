# 复现指南（训练与部署全流程）

> 本文档提供从**数据 → 训练 → 部署**的完整可复现步骤，供评审/他人按此复现本项目。

## 1. 训练启动链

```
train_act_batch.py（批量驱动，主入口）
  │  12 任务队列 + 双卡并行调度 + 预转换
  ├─► process_data.py       数据转换（RoboDojo 新格式 → ACT 标准格式）
  │     └─ 产出：processed_data/RoboDojo/<task>/ + TASK_CONFIGS.json
  ├─► imitate_episodes.py   ACT 训练本体（每任务 2000 epochs）
  │     └─ 产出：checkpoints/RoboDojo-<task>-run1/（policy_best/last + dataset_stats.pkl）
  ├─► 上传 ckpt 到服务器 prepare_case 目录（act-RoboDojo-<task>/run1/）
  └─► 清理本地转换数据（防磁盘堆积）

watch_uploads.py（上传兜底，独立后台）
  └─ 扫描"本地有 ckpt 但服务器缺失"的任务 → rsync 断点续传补传
```

## 2. 启动命令

### 2.1 批量训练（12 任务全自动，推荐）

```bash
# 前提：激活 conda 环境 lyra2（python 3.10 / torch 2.7.1）
conda activate lyra2

# 启动批量驱动（后台运行，日志 /tmp/train_driver.log）
nohup python ~/train_act_batch.py > /tmp/train_driver.log 2>&1 &

# 启动上传兜底 watcher（后台）
setsid nohup python ~/watch_uploads.py > /tmp/watch_uploads.log 2>&1 < /dev/null &
```

驱动自动完成：转换 → 训练 → 上传 → 清理，双卡并行（GPU1 batch16 / GPU0 batch8），预转换消除交接空转。

### 2.2 单任务训练（调试用）

```bash
cd ~/RoboDojo/XPolicyLab/policy/ACT
# 1) 数据转换（自动生成 TASK_CONFIGS.json）
bash process_data.sh RoboDojo <task> arx_x5 joint
# 2) 训练（输出 policy_last.ckpt / policy_best.ckpt / dataset_stats.pkl）
export ACT_ACTION_DIM=14 CUDA_VISIBLE_DEVICES=1
python imitate_episodes.py \
  --bench_name RoboDojo --task_name <task> \
  --ckpt_setting RoboDojo-<task>-arx_x5-joint \
  --ckpt_dir checkpoints/RoboDojo-<task>-arx_x5-joint-run1 \
  --policy_class ACT --kl_weight 10 --chunk_size 50 --hidden_dim 512 \
  --dim_feedforward 3200 --batch_size 16 --num_epochs 2000 --lr 1e-5 \
  --save_freq 500 --seed 0
```

### 2.3 部署到服务器

```bash
# 上传检查点到服务器（rsync 断点续传 + 校验）
rsync -P --partial -e "ssh -o ConnectTimeout=15" \
  checkpoints/RoboDojo-<task>-arx_x5-joint-run1/policy_best.ckpt \
  user@server:~/RoboDojo/XPolicyLab/policy/ACT/checkpoints/act-RoboDojo-<task>/run1/policy_last.ckpt
# 校验（本地 policy_best 与服务器 policy_last 的 MD5 必须一致）
md5sum policy_best.ckpt && ssh user@server md5sum .../policy_last.ckpt
```

## 3. 关键文件清单

| 文件 | 作用 |
|---|---|
| `train_act_batch.py` | 批量训练驱动（12 任务调度、双卡并行、预转换、上传清理） |
| `watch_uploads.py` | 上传兜底 watcher（补传 + 同步演示页/结果） |
| `XPolicyLab/policy/ACT/imitate_episodes.py` | ACT 训练本体（含保存验证最优 `policy_best.ckpt`） |
| `XPolicyLab/policy/ACT/detr/process_data.py` | 数据转换（含逐帧 gzip 压缩） |
| `XPolicyLab/policy/ACT/detr/act_policy.py` | ACT 模型定义（ResNet18 backbone + 动作分块 Transformer） |
| `XPolicyLab/policy/ACT/model_multi_task.py` | 多任务部署模型（`prepare_case` 热切换钩子） |
| `XPolicyLab/policy/ACT/TASK_CONFIGS.json` | 任务配置（数据目录 + episode 数 + 相机列表，自动生成） |

## 4. 环境依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| Python | 3.10（lyra2 环境） | 训练运行时 |
| PyTorch / torchvision | 2.7.1+cu128 / 0.22.1 | 深度学习 |
| NumPy | 1.26.4 | 数值计算 |
| h5py | 3.16 | hdf5 读写 |
| OpenCV | 4.11 | 图像解码/缩放 |
| einops / tqdm / matplotlib | 最新 | 张量/进度/可视化 |
| XPolicyLab / RoboDojo | main 分支 | 评测与策略框架 |

> 网络受限环境依赖安装技巧（pip 源不通时）：见 `docs/06_工程实践与部署经验.md`（SOCKS 代理走阿里源）。

## 5. 数据位置

- **原始数据**：`data/hdf5/<task>/arx_x5/data/episode_*.hdf5`（12 任务 × 100 episodes，含 `state/`、`action/`、`vision/`、`instruction`）
- **转换后数据**：`XPolicyLab/policy/ACT/processed_data/RoboDojo/<task>/arx_x5-joint/`
- **检查点**：`XPolicyLab/policy/ACT/checkpoints/RoboDojo-<task>-arx_x5-joint-run1/`

## 6. 复现验证

1. 训练完成后，服务器 `checkpoints/act-RoboDojo-<task>/run1/` 应含 `policy_last.ckpt`（335,907,847 字节）+ `dataset_stats.pkl`；
2. 评测端发送 `PREPARE_CASE(action_case_id="<task>_case")` 即热切换加载；
3. 用验证集 loss 最优的 `policy_best.ckpt`（即部署的 `policy_last.ckpt`）验证推理正常。
